# rock-sync

Self-hosted, single-user sync for Obsidian. Replaces LiveSync (unreliable) and Obsidian Sync (paid).
Obsidian plugin (client) + Sinatra API (server) backed by git.
The plugin is Rock Sync (id `rock-sync`, prefix `rock-sync-` for its CSS, localStorage keys, view type): `vault-sync` is taken in Obsidian's community list, and Obsidian's update check goes by id. The repo is kovalevtech/obsidian-vault-sync (private), the image obsidian-rock-sync; the server is still vault-sync.

## Dev setup

- Test vault: `obsidian-sync/test-vault` (next to the repo), no symlinks: `npm run dev` builds into its `.obsidian/plugins/rock-sync` (`DEV_VAULT`). Never test on the real vault.
- Plugin build, in `plugin/`: `npm install` once, then `npm run dev` (esbuild watch → the test vault: main.js with an inline sourcemap, so DevTools shows `src/main.js`; `.hotreload`); `npm run build` = minified, no sourcemap, into `dist/`. `plugin/Makefile`: `make phone-install` (build + adb push to `ADB_VAULT`), `make desktop-install` (build + copy to `DESKTOP_VAULT`), both from `plugin/.env.local`.
- Release: Actions tab → Release → Run workflow on `main` (the version commit comes from `github-actions[bot]`), or locally `cd plugin && make patch` / `minor` / `major` = `npm version <level> --no-git-tag-version` (package.json, the lockfile, ../manifest.json, ../versions.json) + a commit and a tag without `v` + `git push --follow-tags` → CI (`.github/workflows/release.yml`, only calling the Makefiles) tests the plugin and the server, pushes the image and, last, publishes the GitHub release with `main.js`, `manifest.json`, `styles.css` from `dist/`: one tag, one version for both. No `manifest-beta.json`: every release is a regular one.
- Devices (phones, iPads) install from Obsidian's community plugins; until it's listed, by hand from a release's three files.
- Lint: `cd plugin && make lint` — the community directory's checks (eslint.config.mjs); 0 errors needed, warnings are advice.
- Tests: `cd plugin && npm test` (`node --test`, no dependencies) — pure modules only: `test/decisions.test.js` covers every row of the decision table; `paths.test.js` (syncable / mergeable / copy names; encodePath over nasty names → request paths CanonicalPath lets through, decoded back), `pairing.test.js` (codes, device names), `bytes.test.js` (hashes = `git hash-object`, BOM included; `exactText`), `blocks.test.js` (conflict labels: UTC written, local time shown).
- Server tests: `cd backend && make test` (Minitest + rack-test, each test on a fresh temp `VAULTS_DIR` and database). `test/api_test.rb` checks every endpoint over HTTP — codes, headers, bodies, commits — independent of the server's insides; it replaces the manual curl set.
- Mobile layout on desktop: `app.emulateMobile(true)` in the console (`false` to go back).
- Hot Reload plugin (pjeby) reloads the plugin on `main.js` / `manifest.json` / `styles.css` change.
- Server: `cd backend && rackup` → `localhost:9292`, serving `sync,mcp` (`.env`'s ENABLED_APPS; `admin` too via `.env.local`). Plugin settings: "Server URL" + a connection code (`make vault-code VAULT=…` or the admin panel) → Connect → Save. Vaults and devices in the dev database `<DB_DIR>/vault-sync.db` (now `../db/vault-sync.db`, repo-relative; created and migrated on first use, its directory must exist): via the admin panel, or `make vault NAME=…` (adopts an existing repo in VAULTS_DIR) and `make vault-code VAULT=…` (a connection code, 10 minutes). Peek: `sqlite3 ../db/vault-sync.db 'select * from devices; select * from pairings'`. The admin page without a browser: render it through rack-test (an `AdminTest` subclass writing `last_response.body`) and `Google Chrome --headless --screenshot`.
- Admin panel in dev: the admin variables in `backend/.env.local` (`PUBLIC_URL` has its dev default in `.env`; `ADMIN_USER`, `ADMIN_PASSWORD`, `ADMIN_TOTP_SECRET` = `make totp-secret`, pasted into 1Password's one-time password field too; `SESSION_SECRET` = `make session-secret`), and `ENABLED_APPS=sync,mcp,admin`, then `localhost:9292/admin`. The variables without `admin` there: "admin env set, admin not enabled"; `admin` without them: exit 1.
- Debug logging: plugin setting "Debug logging" (`debug()` in src/log.js, no restart needed): `console.debug`, the console's Verbose level (the directory's linter allows warn, error, debug).
- Image: `make image` = local build for this machine (`obsidian-rock-sync:<version>` + `:latest`). ### Architecture direction

- Subsystems become small classes the plugin owns: `this.queue = new Queue()`, `this.sync = new Sync(this)`, `this.conflicts = new Conflicts(this)`, `this.files = new Files(this)`. Calls read `this.conflicts.enter(path)` / `this.plugin.conflicts.enter(path)` instead of `this.enterConflict(path)`.
- Classes don't import each other; they talk through the plugin at runtime — no import cycles.
- Pure logic (the decision table, blocks, hashes, paths) stays plain functions without obsidian.
- Migration one subsystem at a time, when it changes for a task anyway. No separate "remove all mixins" step; untouched subsystems may stay mixins. Note: today `this.conflicts` / `this.deleted` are maps of the stored state — those names move into the classes when they're converted.

## Decisions (settled — don't re-litigate)

- Single user. On a stale `If-Match` the server tries a git 3-way merge (`git merge-file`, base = If-Match blob); clean merge → commit `MERGE <path>`, 200 + merged body. Conflicting → 409 + merged text with conflict markers; nothing to merge against → 412 + current server version (see "Conflicts").
- Conflicts live in a working copy, never in the note: the note keeps my text (clean markdown, indexed as usual) and isn't pushed while the conflict is open; the working copy (server's 3-way merge, git markers) is edited in an own CodeMirror view. Deciding the last block writes it into the note and pushes (after a 5 s Undo window). Tried and dropped: markers inside the note, hidden by an extension in Obsidian's editor (Obsidian parses them: setext headings / folding / Outline, blockquotes, server tags indexed; a code block around them was rejected), `@codemirror/merge` inline in the note's editor (ea8126c), side-by-side `MergeView`, a conflict tab with `unifiedMergeView` (client-side diff showed one-sided changes as conflicts and glued neighbours into huge chunks).
- Times from the server are UTC; the client shows them in the device's time zone. The conflict label is `server YYYY-MM-DDTHH:MMZ` (written by the server's merge and by `wholeFileConflict` alike; `serverDate` → local `dd.mm HH:MM`; labels from before, `dd.mm.yyyy HH:MM`, shown as written). The container needs no `TZ`.
- Naming: in code and logs the two sides are `local` and `remote`; in the UI they are "Mine" and "Server". A conflict shows two equal alternatives, not a diff: no word highlights, no green; bars grey (server) / red (mine) / blue (Result).
- Client behaviour: download before edit, periodic upload while editing (Obsidian autosave → `vault.on('modify')`), upload on save.
- Packing: nothing runs `git gc` on its own (yet): every version is a loose, zlib'd object. The admin's Compact (per vault) runs `git gc` in the background, outside the vault lock (git copes with commits meanwhile), `core.bigFileThreshold=50m` (no delta search over big media); reachable objects — every committed version — always stay, unreachable ones (the `hash-object -w` blobs of conflicted pushes) go after git's 2 weeks. Measured on the dev vault (193 MB, mostly media): 1582 loose → 1 pack in 4.6 s, history unchanged — the gain is in text versions, as edits pile up. `git gc --auto` after commits: considered, not done.
- Server storage = git: every write is its own commit; no per-edit branches, no amend (removed: every version a client synced must stay reachable as a 3-way merge base). History bloat from autosaves is accepted.
- One rule for vault paths (`Vault::Path`), for the sync API and MCP alike, before anything touches disk or git: no segment starting with a dot (after HFS-ignorable code points) except the basename `.keep` (`.keep/x` refused; `allowed_hidden?` is where phase 5's `.plugins/<id>/data.json` will go), no empty / `.` / `..` segment, no control character, no `\`, no leading `~`, no `git~1` segment (NTFS's `.git`), valid UTF-8, segments ≤ 255 bytes, path ≤ 1024 → 400 on every route (`Destination` too, GET / DELETE too) / an MCP tool error (hidden → not found, as before). Never `File.expand_path` on client input: a valid path joined under tree/ stays there. `:`, `*`, `[`, a leading `-` are names (git reads them literally). The plugin's `syncable` agrees on hidden paths; it doesn't know the rest (rare: a 400, a grey dot). Paths a vault already holds against the rule: logged at boot (`Vault.report_refused`), never deleted; docs/storage.md tells the cleanup by hand.
- Git is independent of the vault's files: a content store, never a work tree. Writes: `hash-object -w --stdin` (no filters) → index reset to HEAD (`read-tree`) → `update-index --index-info` → `write-tree` → `commit-tree` → `update-ref HEAD new old`; every command `--work-tree=<git dir>`, `GIT_LITERAL_PATHSPECS`. So `.gitignore`, `.gitattributes`, a nested `.git` in tree/ change nothing, no hook or filter of the vault's runs. tree/ is ours: written after the commit (temp files next to their place, renamed into place); a failure up to the commit leaves tree/ and HEAD as they were. Rejected: `git add --force` + `--attr-source` (git ≥ 2.40; the Mac's 2.39 has neither, and the work tree would still be read).
- Everything in git, assets included. No Git LFS. History bloat → rebuild repo later if ever needed.
- File version / ETag = git blob hash `sha1("blob <size>\0" + content)`, computed identically in Ruby and JS.
- Optimistic locking: `PUT` with `If-Match: <base hash>` or `If-None-Match: *` (create only). Identical content = success regardless of headers.
- No client-side E2E encryption.
- One server, many vaults. A device token is for one vault (`devices.vault_id`): a connection code connects one, so a phone with two vaults has two tokens (migration 008 kept tokens with one vault and deleted those with several, from before codes). Every request still names its vault (Basic `<vault>:<token>`); `GET /vaults` gives the token's, as a list (old plugins picked from it).
- Every request carries vault + token as HTTP Basic: `Authorization: Basic base64("<vault>:<token>")`.
- `X-Rock-Sync-Vault: <vault>`: Basic's vault in the clear, for a proxy in front (Cloudflare can't decode Basic) to let only one vault through from outside. Optional (clients from before, the tailnet); when present it must equal Basic's vault exactly, else the same 401 (reason `vault header mismatch`); `DEVICE_ONLY` routes ignore it. Not a boundary by itself (the client sets it): the token → vault check stays the real one; what it adds is that another device's leaked token reaches nothing from outside.
- Canonical request paths, refused at the edge of the app (`CanonicalPath`, config.ru's first middleware): the path a proxy's rules look at and the path the server routes must be one thing. A raw path (PATH_INFO and REQUEST_URI's path, as sent) that doesn't start with `/` (absolute-form — Puma routes its path —, `*`), has an empty segment (`//`; one trailing `/` passes), a `.` / `..` segment, `\`, an encoded `/` `\` `.` (`%2f` `%5c` `%2e`, any case), a control character raw or encoded (`\p{Cc}` after one decode: `%00`, `%0a`, `%7f`, `%c2%85`), or malformed `%` → 400, empty body, one log line (method + path without its query), before routing, the reloader, the request log. Why: the review's bypass — Cloudflare's rules saw `/files/a%2F..%2F..%2Flogin` (dot segments removed, the raw path forwarded), URLMap routed the raw `/admin/../files/…` to Admin, rack-protection's PathTraversal decoded `%2f` and resolved it to `/login`. `%25` passes (decoded once: `%252f` is the text `%2f`). A real client never sends any of it: encodePath = encodeURIComponent per segment (leaves `.`, encodes `%`); only names Obsidian refuses (`\`, control characters) or hides (`.`, `..`) would (a `\` from outside Obsidian on macOS / Linux used to become `/` through PathTraversal; now that push fails, grey dot). PathTraversal kept: on every path that passes it's the identity. A second line, not the proxy's allowlist (docs/exposing.md).
- Tokens: 32 random bytes, base64url, one per device (kind `device`) or per MCP connector (kind `scoped`); real tokens in 1Password. Stored as the SHA-256 hex in SQLite (`devices.token_sha256`); a device token goes only to the plugin (`POST /pair`), a scoped one is shown once at creation. bcrypt rejected: random tokens can't be brute-forced, and a salted hash would mean a bcrypt per entry per request.
- Malformed header, unknown token, revoked token, a scoped token, unknown vault, vault not allowed for the token → the same 401 with the same body, no `WWW-Authenticate` (a browser would pop a login dialog). Never say which vault was expected. The reason goes only to the server log.
- Commit author = who made it, by name and kind: a device token → `<name> <name@device>` (sync API), a scoped token → `<name> <name@token>` (MCP, + `Client: mcp`); the committer stays `sync`. Names are for history, not identity: not unique (migration 009), tokens of either kind may share one (a phone in two vaults, a device connected again), nothing gets numbered. The tools tell it as `author: { kind: device | token | unknown, name }` (`Vault::Author.of`): commits from before the kind (`<name>@vault-sync`) by their trailer (`Client: mcp` → token, else device), the server's own (`sync@localhost`) → unknown. Clients use it: a file last committed by a device = the user edited it. The client sends only software info (`X-Rock-Sync-Client`).
- Client binding = (endpoint, vault name) in the plugin settings. Changing either resets the sync state and enters review mode; changing only the token doesn't. The vault is never typed or picked on the device: it's the code's (the admin chose it).
- Token in vault-scoped localStorage (`rock-sync-token`), per vault and device, never in the vault's files or data.json. secretStorage rejected: its gain is encryption at rest on desktop, while the notes it would protect sit next to it as plain files; Android's app-wide store needed an appId-based id, which changed on a vault rename and lost the token. Any plugin can read it either way; accepted: per-device tokens + revocation. Own key, not inside the settings object (a dump of those can't carry it); never logged. Setting = text field `type="password"`, stored by Save after a successful check. `minAppVersion` 1.8.7 (`saveLocalStorage`). Credentials missing → sync paused + Notice.
- Per-device state lives in Obsidian's vault-scoped localStorage (`app.saveLocalStorage` / `loadLocalStorage`), not data.json: settings (endpoint, vault, debug) under `rock-sync-settings`, the token under `rock-sync-token`, sync state (`base`, `conflicts`, `deleted`, hash cache) under `rock-sync-state`. None of it may travel with the vault: a copied `.obsidian` must not bring another device's `base`. data.json is no longer used.
- Separate vault for the work laptop (not per-folder restrictions), on the same server: multivault, no separate public instance.
- Never sync `.obsidian` (phase 5: except data.json of listed plugins, see below).
- All files are synced: everything Obsidian indexes. The file explorer must show them too: Obsidian hides types it can't open ("Detect all file extensions" off) — a file arrives and doesn't show up. The plugin turns it on once per device (`showAllFileTypes`: `vault.setConfig('showUnsupportedFiles', true)`, Notice; remembered in `rock-sync-all-types-shown`, so turning it off again is respected). Hidden (dot) paths are invisible to the vault API and stay unsynced. Ignore list in `ignored()` (paths.js): `Thumbs.db`, `desktop.ini`.
- Only `.md` is merged, except `*.excalidraw.md` (compressed JSON on one line). `mergeable(path)` in paths.js is the only list. The client sends `Content-Type: text/markdown` for mergeable files, `application/octet-stream` for everything else; the server merges (PUT on a stale If-Match, POST /merge) only for `text/*`, otherwise the existing 412 "nothing to merge". This replaces git's own binary detection: SVG, canvas and excalidraw look like text to git, and a merge with markers breaks them.
- Non-mergeable conflict (412 on push) = keep both: the server version stays at the path; mine moves to `<name> (copy).<ext>` (or `(copy 2)`, … if taken; a compound `.excalidraw.md` suffix is kept whole) and is pushed as a new file. Links not rewritten: `vault.rename`, not `fileManager.renameFile`.
- A conflict copy is recognized by name only, on every device: `X (copy).ext` / `X (copy N).ext` while `X.ext` exists; no state. Actions: "Replace original" (PUT the copy's content to `X` with `If-Match: base[X]`, then delete the copy), "Delete copy". Keep both = the user renames the copy.
- Tree dots: one plugin-owned constructable stylesheet (`document.adoptedStyleSheets`; a `<style>` element is an error for the directory's scanner, none in a WebView without it: no marks), marking the file and all its parent folders via `::after`; one dot per path, by priority: red = open conflict, yellow = conflict copy, yellow ring = waiting for review after a rebind, grey = not synced (a push / delete / move for the path is queued, or its last push failed for good, 413 included).
- Plugin settings sync (phase 5): `data.json` of plugins in an explicit list is stored on the server as `.plugins/<id>/data.json`, independent of `configDir`. rock-sync's own id can never be listed.
- File size limit (default, revisit): server `MAX_FILE_SIZE`, default 100 MB → 413, checked on `Content-Length` before reading the body. The client keeps the path grey and doesn't retry until the file changes.
- Device limit (`DEVICE_LIMIT`, api.js): 20 MB on mobile, none on desktop. The mobile app passes request / response bodies through Java as base64 (256 MB heap): a 36 MB download crashed Obsidian on the Pixel (OOM), in a loop at every start. Bigger server versions become stubs there: an empty file at the path (`stubs[path] = size` in the sync state, `base` = the server version it stands for), shown with a grey ring and a muted name; bar "Not on this device: too large (36 MB)" + Download (`download` op: the GET anyway, the user's call). A stub is never read, pushed, renamed or deleted here (locked like a conflict, folders holding one too); it follows later server versions without a download, is pulled for real once the server version shrinks below the limit, removed when it's gone on the server, renamed along with a remote rename. Deleted / renamed outside Obsidian → not sent, the next check restores it. An empty local file where the server's version is over the limit is adopted as a stub (state lost, rebind). Local files over the limit are never read there either (grey dot, "too large to send from this device") — unless their hash is cached (a Download writes the cache entry). Both changed while the server's version is over the limit → keep both without fetching it (mine as a copy, a stub at the path); review hides Merge / Keep both for them. Known gap: a push / delete racing a server change to a big version still gets the big 412 body.
- MCP endpoint for Claude (claude.ai custom connector: "save this to a note", "what's in X"): opt-in (`mcp` in ENABLED_APPS, see "Apps and processes"): without it `/mcp` is one more unknown path; scoped tokens stay in the database, unusable, until it's back on. The admin's Scoped tokens pages are always there (`/mcp` may run in another process). Its own surface, `POST /mcp`, nothing of the sync API under it. The token comes as `Authorization: Bearer <token>` (the connector: No sign-in + Request headers); nothing secret in the URL (the secret-in-path era — `/mcp/<secret>`, HideSecret, a Puma log patch — is gone, its URLs are 404). Missing / malformed header, unknown / revoked / device token → 401 with `WWW-Authenticate: Bearer`, logged only as "mcp auth failed" (lookup by SHA-256: no timing leak). The log never shows the header, request bodies or MCP answers (read_file's content). The plugin isn't involved: it pulls the commits like any other device's (long poll).
- MCP via the official `mcp` gem (1.8.1), stateless: one `MCP::Server` per request (the token goes in as `server_context`, the grants as `instructions`), `handle_json`, plain JSON answers (202 for notifications), no sessions, no SSE, no transport of the gem's. It didn't fight: tool schemas validated by it (json_schemer), an exception in a tool → JSON-RPC internal error (logged by our `exception_reporter`). Protocol versions: whatever the gem negotiates through `initialize`.
- Scoped tokens (`devices.kind = 'scoped'`): MCP only, the sync API refuses them (and `/mcp` device tokens). The name is the commit author (`Client: mcp`); renamable (later commits carry the new name). Created with a name and its grants (at least one); the admin shows the token once, with the MCP URL (`MCP_BASE_URL` or `PUBLIC_URL`, + `/mcp`) and the header to set.
- Grants (`scoped_token_grants`: token, vault, folder, mode `r` / `w` / `rw`, unique per token + vault + folder): any number of folders in any number of vaults per token; folder `''` = the whole vault (typed as empty or `/`, the new row's default). A path's mode = the union of the modes of every grant holding it in that vault, by segment (`Notes` doesn't hold `Notes2/x.md`): a nested grant only adds, it never takes away. No grant → not found. `r` = list_folder / read_file, `w` = write_file / append_file, `rw` (from one grant or several) = delete_file too. Each grant may have a purpose (`purpose`, '' = none; up to 2000 characters, `\n` line breaks, trimmed): the admin's note on what the folder is for and how to use it; MCP shows it after the grant in `instructions` (further lines indented) and in `list_access`, as the user's instructions to follow. Saved as a whole (the admin's form), each row checked: vault exists, purpose not too long, folder normalized (no slashes around it; no `..` / `.` / empty / hidden segment), no folder twice in a vault, and no row whose mode adds nothing to what the (otherwise fine) grants on its ancestor folders give ("`r` on Claude/Inbox has no effect: Claude already gives rw."). Grants that wouldn't pass any more (a folder renamed under another grant) keep working; the list marks their token "check grants", its page shows the error, a save needs it fixed. Hidden paths (`.plugins/`, `.obsidian`, `.keep` files — any dot segment) are never grantable, listed, readable or writable. Subfolders made by a write get their `.keep` in the same commit (`WriteFile keeps:`), like the plugin's folders.
- Grants follow folder renames: a commit moving `X/.keep → Y/.keep` (MoveFile) moves grants on `X` and below it (`X/…`) to `Y/…`, in that vault, for all tokens; a nested folder's own `.keep` move then finds nothing left (either order works). A grant already at a new folder for that token can only dangle (else the move was a 409): replaced. Nothing else is created or changes mode. A rename landing a granted folder under another grant isn't checked: the redundant row shows its error on the token's next save. A failure there is logged, the move stands; dangling grants are fine (the admin marks them "folder missing").
- MCP tools: whatever a token may not do with a path reads exactly like a path that isn't there ("`X` not found in notes."; a vault it has no grant in: "Vault `x` not found.") — no folders listed, no hint either way. Write results are `{ status, path, etag }`, never file content. `write_file` without `base` = create only (`exists`, nothing written); with `base` = a strict If-Match, never merged (`stale`, nothing written; the current etag only where the token may read — no blind overwrite of a version it can't see). `delete_file` needs `rw` and `base` (`stale` + the current etag; already gone = `gone`, success). `read_file`: UTF-8 text without NUL, at most `MCP_MAX_WRITE`; else an error with size and etag (no base64). `list_folder`: files only, from HEAD; a folder above the grants lists just their parts; last commit per file in one `git log` walk (`Git#last_commits`, stopped once all are found). `append_file`: no base, no conflicts (read + write under the vault lock), a line break first unless the file ends with one, missing → created, not UTF-8 → error, empty text → nothing. No extension → `.md` (every tool). Every tool takes `vault`: required when the token's grants are in several vaults, optional with one. The tool list is the same for every token (not filtered by its grants).

## API

Auth (every route, unknown ones included; exemptions = `App::PUBLIC`: `/health`, `/pair`; `/mcp` isn't App's, see "MCP" below): `Authorization: Basic base64("<vault>:<token>")`, parsed only in App's `before` (before the 413 check) → device by the token's SHA-256 (`Devices.authenticate`; revoked → refused) → (`App::DEVICE_ONLY` routes, `/vaults`: done, the vault part ignored, may be empty) the device's vault → `Vault.find` → `Devices.touch` (last seen). Any failure → 401 `{"error":"unauthorized"}`, no `WWW-Authenticate`; the reason is logged with `VERBOSE_HTTP_LOGS` on, else nowhere (`env['vault_sync.auth']`: `no Basic credentials`, `unknown token`, `revoked token`, vault not allowed / missing), the header never. Paths are vault-relative (`Destination` too). Every answer: `Cache-Control: no-store` (see Gotchas: `requestUrl`'s cache). `X-Rock-Sync-Client: plugin=…; obsidian=…; platform=…` (optional) → `Client:` trailer of the request's commits (printable ASCII only, CR / LF stripped, ≤ 200 chars). `X-Rock-Sync-Vault: <vault>` (optional; the plugin sends it whenever the vault isn't empty) must equal Basic's vault, else the same 401 (reason `vault header mismatch`); `DEVICE_ONLY` routes ignore it. A proxy in front (Cloudflare) filters by it. Commit author = device name, `<name>@device`; committer stays `sync`.

Done:
- `GET /vaults` — `{"vaults": [names]}`: the vaults the token may use (with their repo present). Basic as usual, the vault part ignored. The plugin no longer asks.
- `DELETE /token` — the token revokes itself (`App::DEVICE_ONLY`: the vault part ignored): 204. The plugin's Remove, a replaced connection, an unsaved draft.
- `GET /health` — 200 `ok` (text/plain), no auth (`App::PUBLIC`), says nothing about vaults or tokens; not logged (Docker's healthcheck every 30 s). Other methods on it → 404, like any unknown route.
- `POST /pair` — no auth (`App::PUBLIC`, the code is the credential). JSON `{ code, name }`, at most `PAIR_MAX_BODY` (1 KB) read → 200 `{"token":…, "vault":…, "name":…}` (a device token for the code's vault — new, under the name sent even if others have it, or a Reconnect's new secret under the row's name; never in a log, config.ru's `QUIET_BODIES`), 400 not a JSON object, 401 `{"error":"unauthorized"}` wrong / used / expired alike (a Reconnect whose token was revoked meanwhile too), 422 `{"error":…}` bad name (the code stays), 429 over the limit. Other methods → 404.
- `PUT /files/*path` — body = raw bytes. `If-Match` / `If-None-Match: *`. 204 + `ETag: <hash>` (unquoted). Stale `If-Match` → 3-way merge (`git merge-file`; base = the If-Match blob, current server version first, mine; my version is stored as a blob first, `hash-object -w`): clean → committed, 200 + merged body + `ETag`; conflicts → nothing written, 409 + merged text with git's conflict markers (`--marker-size=9`: a line of seven `=` in a note would read as the separator; labels `server <UTC, ISO 8601 to the minute: YYYY-MM-DDTHH:MMZ>` / `mine`; `merge.conflictStyle` pinned to `merge`) + `ETag` / `Last-Modified` of the current server version. Merged only when the request's `Content-Type` is `text/*` (`mergeable?` in app.rb; the plugin sends `text/markdown` for notes, `application/octet-stream` for the rest). 412 when there's nothing to merge (not `text/*`, base unknown to git, binary, `If-None-Match: *` on an existing file): body = current server version + `ETag` + `Last-Modified`; empty body if the file is gone. 400 bad path. 413 body over `MAX_FILE_SIZE` (Content-Length; Puma refuses it before buffering, app.rb's `before` filter for other servers / tests).
- `DELETE /files/*path` — `If-Match` = the version the client deleted. Matches → `git rm`, commit `DELETE <path>`, 204; empty dirs in `tree/` pruned. Already gone → 204. Edited elsewhere → 412 + current version (`ETag`, `Last-Modified`), nothing deleted.
- `POST /move/*from` — `Destination: <to>` (URL-encoded like the request path). Paths only, no `If-Match`: whatever version is at `from` moves (`git mv`, one commit `RENAME <from> → <to>`, so `git log --follow` keeps the history), 204 + `ETag` at `to`. `to` taken → 409, `from` missing → 404.
- `POST /merge/*path` — dry run of PUT's merge (`If-Match` = base, body = my version, `Content-Type` as for PUT): 200 + clean text or 409 + text with markers, `ETag` / `Last-Modified` of the current server version; 412 / 413 like PUT. Never writes.
- `GET /files/*path` — raw bytes, `ETag: <hash>` (unquoted), `Last-Modified` (last commit touching the file). `If-None-Match: <hash>` equal to the current one → 304, no body. 404 if missing.
- `GET /manifest?v=1` — `{ version: <HEAD sha>, files: { path => [hash, size] } }` from `git ls-tree -r -l -z` (size in bytes: the client's `DEVICE_LIMIT`). Without `v` (v0, clients from before sizes): `files: { path => hash }`. Same ETag for both. The client asks only through `manifestUrl` (api.js). Sinatra `etag` helper → quoted ETag, 304 on `If-None-Match`; before the first commit `version` is null and the ETag `no-commits` (`App::NO_COMMITS`: without one a client's polls have nothing to wait past). Client must echo the header as-is.
- Long poll: `GET /manifest?wait=N` with `If-None-Match: <version>` holds the request until HEAD moves past that version (then 200 + manifest) or N seconds pass (≤ 60, then 304). Without `If-None-Match`: answers right away. `ChangeFeed` (`backend/lib/change_feed.rb`), one per vault (a commit in another vault doesn't answer the poll): every commit calls `feed.notify` (broadcast); `wait` checks the version and sleeps under one mutex, so a commit can't slip between. One Puma thread per waiting client: `backend/config/puma.rb` (`threads 0, 16`, read by `rackup`). Ctrl+C / TERM: `config/puma.rb` chains `ChangeFeed.close_all` (wakes every poll of every vault, none waits again; in a thread — a trap handler can't take a mutex) before Puma's own handler, so the graceful stop doesn't sit out the waits; `force_shutdown_after` would instead kill any request, a commit included. Dev reloader (`config.ru`): reloads only when a file under `lib/` or `services/` changed (mtimes), one request at a time; `?wait=` requests skip that lock (they'd hold up everything) — a reload first closes them (`ChangeFeed.close_all`: they answer, clients ask again; the client counts that quick 304 as a failure and backs off 5 s), waits until they're out, and new polls wait for it. A poll running across a reload got `NameError: uninitialized constant VaultService` (the server's former all-in-one class). WebSockets / SSE rejected as overhead for a one-way "re-read the manifest" signal; HTTP/2 doesn't help (server push is gone).

MCP (`mcp_endpoint.rb` + `lib/mcp_tools.rb`; outside App, no Basic; the rules: Decisions → Grants, MCP tools):
- `POST /mcp` with `Authorization: Bearer <token>` (a scoped token, active; the scheme case-insensitive). JSON-RPC 2.0 per MCP Streamable HTTP, stateless: `initialize` (`instructions` = the grants per vault with their purposes, list_access, when to name the vault), `notifications/initialized` (→ 202, no body), `tools/list`, `tools/call`, `ping`; answers `application/json`. No / bad header, unknown / revoked / device token → 401 `{"error":"unauthorized"}` + `WWW-Authenticate: Bearer`. Body over `MAX_FILE_SIZE` → 413 (after the token). `GET` / `DELETE` / anything but POST → 405 + `Allow: POST`. Any other path under `/mcp` (`/mcp/<old secret>` too) → 404 with an empty body, like App's unknown routes.
- Tools, each with `vault` (required with grants in several vaults, else optional); paths vault-relative, no extension → `.md`; anything not granted → "not found":
  - `list_access()` → `[{ vault, folder, mode, purpose? }]` (`/` = the whole vault; `purpose` only when set). Any grant.
  - `list_folder(path?, recursive = true)` → `[{ path, etag, size, modified_at, author }]`, sorted; files only (no `.keep`, nothing hidden), only what `r` covers; `path` may be above the grants (the root by default). Needs `r`.
  - `read_file(path)` → `{ path, etag, content, modified_at, author }`; binary / over `MCP_MAX_WRITE` → error with size + etag. Needs `r`.
  - `write_file(path, content, base?)` → `{ status: written | unchanged | exists | stale, path, etag? }` (commit `PUT`); `base` = strict If-Match. Needs `w`.
  - `append_file(path, text)` → `{ status: appended | created | unchanged, path, etag }` (commit `APPEND`). Needs `w`.
  - `delete_file(path, base)` → `{ status: deleted | gone | stale, path, etag? }` (`DeleteFile`: commit `DELETE`, empty dirs pruned; etag after stale). Needs `rw`.
  - `etag` = git blob hash (as the sync API's); `modified_at` = the last commit touching the file, UTC ISO 8601 (`YYYY-MM-DDTHH:MM:SSZ`); `author` = `{ kind: device | token | unknown, name }` of that commit.
  - Errors (`isError: true`, text): rate limit, size, bad path, which vault, not found, a folder, binary / not a text file.

## Client sync algorithm

Rebind (Save with another endpoint / vault, or the first one; refused while a conflict is open): `rebind()` pauses the queue, stops the poller, waits for the running item (`queue.idle()`: a request in flight can't be aborted, its answer must not land in the new state), clears the queue, switches the credentials, resets `base`, `deleted`, `tooLarge`, the hash cache, `failed`, `review`, sets `firstSyncDue` and resumes. The first manifest check (`decide(…, firstSync)`, empty base): identical → base, server only → pull (approved by Save), only here → `review[path] = 'local'`, both and different → `'differs'`; `.keep` alike (a folder). Review marks (sync state) are never sent: `pushItem` skips them, modify doesn't queue a push, a rename moves the mark, a delete drops it (nothing sent). Every later check re-evaluates them (identical → base, here only → `local`, both → `differs`, gone here → mark dropped, then the normal rules). Decisions (bar, modal "Review files from first sync" with bulk actions) are queue ops (`first-sync.js`); the mark goes when the op runs (until then a check keeps it) and comes back if it fails: `local` → Push (PUT `If-None-Match: *`; 412 → conflict / keep both as usual); `differs` → Take server (pull), Keep mine (base = the server's hash from the last manifest, then a normal push: `If-Match` it, merged / 409 / 412 as usual), Merge (mergeable: GET, one whole-file block, `base: null`, the conflict view), Keep both (non-mergeable: `copies.keepBoth` with the GET's answer). After the first sync a Notice counts what waits (click → modal). Tree: yellow ring (`--rock-sync-dot-review`, default the copy color; `--rock-sync-ring-width` 1.5px, same outer size as a dot).

Per-device `base` map (path → hash last synced) in the sync state (`rock-sync-state` in vault-scoped localStorage, `saveState()`).
Files: every type (`syncable`). Hashes always over raw bytes (`readBinary`); the manifest check caches them per device (`hashes[path] = [mtime, size, hash]` in the sync state, `localHash`: only changed files are read; entries of gone files dropped). Writes: notes (`isMarkdown`, excalidraw too) through the text APIs (`vault.modify` / `create`, `process` for merges) so an open editor keeps its cursor — decoded by `exactText`, so the bytes on disk stay the server's (a BOM kept; not UTF-8 → binary API); everything else `modifyBinary` / `createBinary`. PUT / POST /merge send `contentTypeOf(path)`. Too large (413): `tooLarge[path] = [mtime, size]` in the sync state, Notice; while the file keeps that mtime + size (`isTooLarge`) it is never read, hashed or sent again — pushes skip it, the manifest check leaves it out of the comparison altogether (not "gone here", which would DELETE it on the server); the mark follows a rename, a delete or any answer to a push drops it. Big files don't belong in git: another store for them maybe later. `failed` (in memory, a Set): a push that failed for good — an unexpected status, or no answer after all retries (`failingFor`, also for `move`'s target); pushed again on the next change or manifest check; cleared by any answer to the next push, a push that finds the file back at base, a local delete, a rename (the move pushes the new path).
- Every tree mark is explained by a bar when the file is open (`Bars`, by priority: deleted, conflict copy, "Not synced: too large for the server (458 MB)", "Not synced: the last upload failed" + Retry). None for a conflict (its own view) or a push just queued (too brief: it would jump at every autosave). Files Obsidian can't open (no view, e.g. `.af`) can't show one. Re-rendered with the tree marks on every queue change. Non-mergeable 412 (changed on both sides): keep both, see "Conflict copies".
Credentials (`credentials.js`, settings tab): endpoint + vault + device (the token's name) in `rock-sync-settings`, token in `rock-sync-token` (both vault-scoped localStorage). Every request: `Authorization: Basic base64("<vault>:<token>")` + `X-Rock-Sync-Client: plugin=<manifest.version>; obsidian=<apiVersion>; platform=<android|ios|macos|windows|linux>`. The tab: status card, then Connection — connected: Server / Vault / Device + Edit / Remove; else (or Edit) the form: Server URL, Connection code (the admin's connection link pasted into either fills both: `linkOf`), Device name → Connect (`POST /pair`, see Decisions) → a draft; `GET /manifest` with it, one attempt: 401 → "The server refused the new token", anything else failing → "Server unreachable"; 200 → the local manifest (`localManifest`, progress) and a summary "<vault> on <host>, as <name>. Identical N · only here N · only on the server N · different N" → Save = rebind (below). The running sync keeps the saved credentials meanwhile. Paused sync (`pauseSync(reason, { notice })`, `this.pausedFor`: `credentials` = not connected (at startup, or after Remove: no Notice then), `unauthorized` = a 401 at runtime for the saved credentials): queue paused (items kept, the running one re-run first, not marked failed), poller stopped, one sticky Notice that opens the settings; `resumeSync` (Save) resumes the queue, queues a manifest check, starts the poller.
Sync status (`status.js`): error = sync paused (`pausedFor`) or an unexpected failure (a queue item throwing anything but `NoAnswer` / an abort; push / delete / move with an unexpected status) newer than the last answer from the server (`lastOk`: any answered request of the running sync, polls included — the next answer clears it); offline = the poller backing off; syncing = queue items; else synced. Icons `cloud-check` (green) / `refresh-cw` / `cloud-off` (muted) / `cloud-alert` (red), each with a fallback name if this Obsidian's Lucide lacks it; tooltip = state + last contact or the error. Placement (`ui/status-icon.js`), next to the vault name: desktop `.workspace-sidedock-vault-profile .workspace-drawer-vault-actions` (first, before help / settings), mobile `.workspace-drawer.mod-left .workspace-drawer-header` (a `.workspace-drawer-header-icon.mod-raised` before `.mod-settings`). Internal DOM, so: checked on every status change, `layout-change` and the workspace's class change (sidebar collapse); a MutationObserver (childList) on the container and each ancestor puts it back right after Obsidian re-renders or replaces any of them; container not found, or desktop left sidebar collapsed → the same icon in the ribbon (`addRibbonIcon`, created once, hidden with `.rock-sync-hidden` otherwise). Click → the plugin's settings. Settings top block (live while open): state, last successful sync, last error / pause reason, queue length; Retry for error / offline (`retrySync`: after a 401 the saved credentials again, else failed pushes + a manifest check + a poll right away; not for missing credentials).
Triggers: startup (`onLayoutReady`: manifest check, then long polling), foreground (`visibilitychange` → visible: manifest check + `poller.wake()`, ending a back-off wait), back online (the poller's first answer after failures queues a manifest check: offline edits go up, failed pushes retried), push on `modify`, long polling (`poll.js`, `this.poller`): `GET /manifest?wait=25` with `If-None-Match` = `manifestEtag` (set by every manifest check and poll answer), asked again right away; a 200 queues a full manifest check only if `manifestChanged` (decisions.js: the manifest differs from base / open conflicts' server versions — own pushes move the version too, and a full check hashes every file). Failures (offline) back off 5 s → 60 s; a 304 faster than 1 s (server or proxy not holding polls) counts as a failure, no spinning. 25 s: below mobile `requestUrl`'s own timeout. A poll in flight can't be aborted: `stop()` drops its answer.

All sync work goes through one plugin-wide queue (`this.queue.enqueue(op, path)` → `drain()`), one item at a time:
- Ops: `push`, `pull`, `delete`, `move` (`from→to`), `manifest`, plus `refresh` / `resolve` for conflicts. Items are `op:path` keys, not contents; a key already waiting is not added twice.
- `push` reads the file when it runs, not when queued — autosaves during a slow request collapse into one push.
- `push` skips when local hash = `base[path]` (nothing new; an applied merge doesn't bounce back). Pulls write inside `withoutEcho` and `modify` skips those paths: no push queued behind other pulls (it would show the path grey meanwhile).
- `manifest` only decides and enqueues pulls/pushes; they run as separate items after it.
- Enqueuing the key that is running aborts its pending retries (the queued copy redoes it with fresh state).
- One failing item doesn't stop the queue. `onunload` clears the queue and aborts the running item.

### Folders, deletions, renames

Path and content sync separately: a rename is a path operation; content keeps going through PUT / the server's merge. Edits are never lost, and nothing is deleted here without confirmation.

- Folders = `<folder>/.keep` on the server: an empty file in git. Never created in the vault — the folder is the local side (virtual file, hash `EMPTY_HASH`, part of `local` in the manifest check; `localFile()` maps it to the TFolder). Folder created → push `.keep`; deleted → delete `.keep`; renamed → move `.keep` (+ one `move` per file inside, Obsidian reports each). Pre-existing folders: "no base, only here" → push. `.keep` on the server → `createFolder`. A folder is never deleted for being empty.
- Local events (`registerFileEvents`, registered on layout ready — at startup Obsidian reports everything as created): `create` → push, `delete` → op `delete`, `rename` → op `move`; folder events act on the `.keep`. Paths in `applying` (see `withoutEcho`: our own renames / trashes for the server) are skipped. A queued push of a path that's gone is skipped.
- `delete`: no base → nothing. 204 → base dropped. 412 (edited elsewhere) → that version written back, marked `deleted` (reason `edited`, `serverHash`).
- `move`: no base → push the new path. 204 → `base[to] = base[from]`, then a normal push of `to` (content merged if edited elsewhere). 409 (`to` exists on the server) → push `to` as create (→ 412 → conflict) and delete `from`. 404 (deleted elsewhere) → base dropped, `to` marked `deleted`.
- Manifest: in base and gone on the server → never deleted here: `deleted[path] = { deletedAt, reason: 'remote' }`, base dropped; marked paths are skipped by later checks. In base and gone here → `DELETE` (deleted while the plugin wasn't running; edited on the server → 412 → restored + marked). Gone on both → base dropped.
- Remote renames (`applyRemoteRenames`, before the table): a path gone from the server and unchanged here + exactly one new path with its content (and no other gone path with it) → `vault.rename` (keeps tabs; not `fileManager.renameFile`, link updates arrive as ordinary pulls). Folders at once: `a/.keep` gone, `b/.keep` new, and every synced file under `a/` reappears under `b/` unchanged (all `.keep` share one hash; an empty folder renamed is indistinguishable from delete + create — left to the normal rules). A conflicted note matches by its conflict's `serverHash` instead (my text differs anyway) and takes the conflict along (`moveConflict`: state, working copy, tabs; the reloaded view schedules a pending auto-push again); the lock below lets these renames through (`applying`).
- `deleted` marks (sync state `deleted[path] = { deletedAt, reason, serverHash? }`): file tree struck through and muted (same stylesheet as the dots); a bar (`Bars`: in notes above the title, inside the scrolling note — `.cm-sizer` / `.markdown-preview-sizer`, on phones the header floats over the view's top; other views — image, PDF, audio, video, canvas — at the top of `view.contentEl`) ("Deleted on another device · dd.mm HH:MM" / "Edited on another device after you deleted it · …") with "Delete" (trash here; `edited`: DELETE on the server too) / "Keep" (push as create). Editing a marked file = Keep; deleting it = Delete; renaming moves the mark. Command "Review deletions from other devices": modal with all marks, per item and Delete all / Keep all. A folder's Delete trashes it with its content.
- Files with an open conflict (or folders holding one) can't be renamed or deleted: Obsidian can't cancel these after the fact, so `fileManager.renameFile` / `trashFile`, `vault.rename` / `delete` / `trash` are wrapped while the plugin runs (Notice "Resolve the conflict first"). Renamed outside Obsidian → Notice, not synced. Renamed / deleted on another device: see "Conflicts".

### Conflicts

Scope: concurrent edits the server couldn't merge (same lines changed on both sides).

- Note during a conflict = my text only; never pushed or pulled until resolved. Changed outside the conflict view meanwhile → Notice only (resolving replaces it). Working copy = the server's 409 body (`git merge-file` output) in `<plugin dir>/conflicts/<vault path>` (`vault.adapter`; `.obsidian` is never indexed or synced). 412 (nothing to merge) → the client builds the same format, the whole file as one block (`wholeFileConflict`). `conflicts[path] = { serverHash, savedAt, base, since }` in the sync state: server version merged against (the resolving push sends `If-Match: serverHash`) and its commit time, the base the merge started from (null for whole-file blocks).
- Push → 409/412 (`enterConflict`): only if the note is still what was sent (else its queued push merges again); writes the working copy, opens tabs of the note as the conflict view.
- Server version changed during the conflict (queue op `refresh` → `refreshRemote`: conditional GET with `If-None-Match: serverHash`; on file-open of a conflicted note, every `REMOTE_POLL_INTERVAL` (15 s) while its view is open, on layout ready, from the manifest check): `POST /merge` with `If-Match: base` and the note (my text); no base or 412 → whole-file block. The result replaces the working copy (decisions so far are lost, accepted), open views reload. `/merge` failing with anything but 412 changes nothing. Working copy missing while the conflict is open → merged again (`recoverWorkingCopy`).
- Note gone on the server during the conflict (another device deleted or renamed it): `refresh` → 404 and the resolving push → 412 with an empty body only queue a manifest check, which tells the two apart. Renamed → the conflict moves with the note (`applyRemoteRenames`). Deleted → the conflict closes (working copy removed, tab back to the note, Notice) and my text stays, marked `deleted` (reason `remote`): Keep pushes it as a new file. A rename whose new path is already here (pulled while the conflict blocked the rename) counts as a deletion.
- `ConflictView` (`ItemView`, type `rock-sync-conflict`, `navigation = true`): own `EditorView`, no Obsidian markdown — `history` + default keymaps (Cmd+Z), line wrapping, our extensions. Edits saved to the working copy debounced (`SAVE_DELAY`), flushed on close and before resolve. Tabs showing a conflicted note switch to it (`showConflict` on `layout-change`, matching `leaf.getViewState().state.file`: on file-open, and for deferred tabs, `leaf.view` doesn't have the file yet); back to the note after resolve. Header (`titleEl`): `Conflict · i/N ↑ ↓ · server dd.mm.yyyy HH:MM`, arrows jump between blocks. Tab title: `<note> (conflict)`.
- Editing model: `findBlocks` parses `{ start, mid, end }`; `mid` null = Result (separator deleted, one text). Marker lines replaced by block widgets and atomic for the cursor (`atomicRanges`, with the line breaks around them). Start / end markers (with those line breaks) protected by `changeFilter` (`protectMarkers`) — removed only by buttons. The separator may be deleted, always whole: Backspace at the start of my side / Delete at the end of the server side joins the two lines; a selection across both sides deletes like plain text; typing right at it goes into the adjacent side (`editSeparator` transactionFilter — also normalizes Android's raw DOM edits). Back to two blocks = Cmd+Z. Both sides editable.
- Buttons: two sides → "Take server" / "Keep mine" / "Both"; once the block's text differs from the loaded working copy (`loadedBlocks`; undoing back restores the choices) → "✓ Done" = keep the text as shown; Result → "✓ Done". They replace the whole block, markers included (`decide`, `ownEdit`, undoable).
- Look: each block one card (`--background-secondary`, radius 8px, 12px from the text around it) from widgets (top caption, mine caption, buttons) and lines with the card background; captions "Server · dd.mm HH:MM" (`cloud`) / "Mine" (`smartphone` / `monitor`) / "Result" (`git-merge`), first line inside their side's bar; bars 2px drawn as a background gradient at the card padding, continuous grey → red; server lines `spellcheck="false"`. Trailing blank lines of a side (not its first line, not the one with the cursor) are hidden with the marker after them. Same on mobile.
- No blocks left (view update listener, or on load) → `scheduleResolve`: Notice "… pushing in N s" counting down, text and "Undo" side by side (`.rock-sync-notice-row`; Undo cancels, undo in the view), after 5 s `resolve(path)`: working copy → note (`writeNote`, its modify isn't "outside"), queue op `resolve` → PUT with `If-Match: serverHash`. 204 → base set, conflict cleared, working copy removed, tab back to the note. 200 → cleared, merge applied. 409 → new working copy, conflict stays.
- Tree marker: plugin-owned stylesheet (`TreeMarks`) with `.nav-file-title[data-path=…]` / `.nav-folder-title[data-path=…]` for the file and all parent folders, a dot via `::after` after the name, one per path by priority (red conflict > yellow copy > yellow ring review > grey not synced: `queue.pending()` + `failed` + `tooLarge`; a `.keep` marks its folder); rebuilt from `conflicts`, the vault's copies, the queue (vault create / delete / rename and every queue change → `schedule`: at most every 300 ms). Size and colors: `--rock-sync-dot-size`, `--rock-sync-dot-conflict`, `--rock-sync-dot-copy`, `--rock-sync-dot-pending` in styles.css. A dot sits right after the name: in marked rows the file type tag (non-markdown files, pushed right by its auto margin) gets `order: 1`.
- Conflicts from the markers-in-the-note era (`mine` in their state) are migrated on load (`migrateLegacyConflicts`): note restored from `conflicts/<mine hash>`, then merged again.

### Conflict copies

Non-mergeable files (`!mergeable`: everything but `.md`, excalidraw included) changed here and elsewhere: the push gets 412 + the server version (stale If-Match, or create on a taken path — push on modify, manifest both-changed, move 409). `copies.keepBoth`, only if the file is still what was sent (else its queued push retries): `vault.rename(path → copyPath)` and the 412 body written to `path` (`writeLocal`), both in `withoutEcho`; `base[path]` = its ETag; push of the copy (create); Notice. Empty 412 body → manifest check, as for notes.
- A copy = by name (`copyOrigin`) while its original exists (`originOf`): no state, same on every device; renaming it to anything else = keep both. A copy's own copy is numbered after the original (`X (copy 2).ext`).
- Bar on a copy "Conflict copy of X": "Replace original" (copy's bytes written to X here → its modify pushes it with If-Match: base[X], a newer server version → keep both again; copy trashed → its delete event DELETEs it) / "Delete copy" (trash → DELETE). Command "Review conflict copies": modal, per item Open / Replace original / Delete copy.
- Yellow dot on the copy and its parent folders.
- In-view bars sit above content positioned over the whole view (`position: relative; z-index: 1`; canvas: clear of its control column).

| Situation | Action |
|---|---|
| conflict, gone on the server | close the conflict, mark `deleted` (gone here too: drop base) |
| marked `deleted` | nothing until Delete / Keep |
| local = remote | nothing, set base (a review mark dropped) |
| first sync or review mark, no base, here only | review `local` |
| first sync or review mark, no base, both, different | review `differs` |
| review mark, gone here | mark dropped, then the rows below (server only: pull) |
| in base, gone on the server (changed here or not) | mark `deleted` (reason `remote`), drop base |
| in base, gone on both | drop base |
| in base, gone here | DELETE with If-Match: base (412 → restore + mark `edited`) |
| server only | pull |
| local = base, remote changed | pull |
| remote = base, local changed / no base, local only | PUT (If-Match: base / If-None-Match: *) |
| both changed / both created | PUT with If-Match: base → server 3-way merge; 409 / 412 → conflict view |
| gone on the server + same content at a new path (unchanged here; conflicted: its server version) | rename here (before the table) |

Implemented in `src/decisions.js` (renames: `applyRemoteRenames` in `sync.js`, before the table). Local files are re-hashed only when mtime / size changed (`localHash`).

## Gotchas learned

- Collapsing / expanding a sidebar doesn't fire `layout-change`; the `.workspace` element's classes (`is-left-sidedock-open`) change.
- Desktop CDP lists every Obsidian window as a page (Settings is a popout `about:blank` without `app`): pick the main one by url `app://obsidian.md/index.html`.

- Obsidian 1.14 opens Settings as a popout window: a Notice shows in the active window (there, while Settings is open). So the linter's `activeDocument` (prefer-active-doc) is wrong for what belongs to the main window — the tree marks' stylesheet, the status icon, `visibilitychange`: the plugin may load while Settings has the focus. Those use `window.document` (the rule lets a property access through). Since 1.8.7 `Notice.noticeEl` is only the message (`.notice-message`); the whole notice is `containerEl`.
- Android: `app.appId` is the vault's absolute path (`/storage/emulated/0/…`), so localStorage keys are `<path>-<key>`. Renaming a vault in the vault manager (Obsidian 1.14.4) moves its localStorage keys to the new appId (settings, token, sync state survive), but not `enable-plugin-<appId>`: the renamed vault opens in restricted mode, community plugins have to be turned on again. Mobile CDP target: the page's url isn't `app://` (match the title "… - Obsidian"); `Page.captureScreenshot` hangs there — `adb exec-out screencap -p` instead.
- Desktop: `app.appId` is the vault's key in Obsidian's vault list (16 hex chars), kept when the vault is renamed / moved in the vault manager (main process `vault-move` only changes the path); a vault that gets a new appId (e.g. its folder renamed outside Obsidian) loses its localStorage (settings, token, sync state).

- Puma's `ErrorLogger` (parse errors such as a 413 from Content-Length, unknown errors) writes `"<method> <REQUEST_PATH>"` straight to stderr — `log_formatter` doesn't apply to it: never put a secret into a path.
- Rack middlewares that log (rackup's CommonLogger in development) read `PATH_INFO` from env after the response: a middleware rewriting env in front of everything masks them too; `Rack::URLMap` restores what it found, i.e. the masked path.
- Sequel's `add_column … check:` on SQLite drops the CHECK silently (and `add_constraint` rebuilds the table): migration 003 adds `devices.kind` with plain SQL.
- `Sinatra::NotFound` is a `StandardError`: an `error StandardError` handler sees unknown routes too (App maps it by name to 404).
- Headless Chrome on the Mac won't make a window narrower than ~500px (`--window-size=400,…` just crops): screenshot a phone layout through an `<iframe width="390">`.
- `Rack::Auth::Basic::Request` also reads `X-HTTP_AUTHORIZATION` and decodes base64 leniently: App parses `HTTP_AUTHORIZATION` itself (`unpack1('m0')`, strict).
- `App.routes` lists HEAD for every GET: the default-deny test iterates it, so a new route is covered without touching the test.

- Rack 3 + `rackup` in development adds `Rack::Lint`: header names must be lowercase; `rack.input` has no `rewind`.
- Logging middleware logs `req.GET`, not `req.params` — `params` parses form bodies and consumes `rack.input` (curl defaults to form content type → empty file in the vault).
- `Bundler.require` must load `sinatra/base` (`gem 'sinatra', require: 'sinatra/base'`), not classic sinatra.
- Sinatra in development raises before `error` handlers unless `show_exceptions` is off: App, Admin and McpEndpoint keep it off. A 5xx still reaches the log with its trace (Sinatra's `dump_errors`, off only under `RACK_ENV=test`); the client gets an empty 500.
- `File.expand_path` expands `~user` (and `~`) at the start of its argument: on client input `~root/x` was another home before any escape check, `~nosuchuser` an ArgumentError (500). `Vault::Path` never expands; it refuses `..` instead. Over HTTP `..` never gets there anyway: CanonicalPath refuses it (and `%5C`) in config.ru; App alone (rack-test) has rack-protection's cleanup, which turns an encoded backslash (`%5C`) into `/` (`a\b.md` arrives as `a/b.md`).
- What git did with vault files when it staged from tree/ (`git add` / `mv` / `rm`, before the content store): a `.gitignore` with `*` → every later add failed ("paths are ignored"), the file left in tree/; `.gitattributes` (`eol=crlf`, `working-tree-encoding`) → other bytes stored than sent (ETag ≠ manifest, sync loop); a `.git` segment → silently skipped by `add` (commit failed, file left in tree/), `mv` to `x/.git/hooks/…` committed the source's removal only; a nested `y/.git` made `y/` unwritable (a submodule to git); pathspec magic in names (`:/b.md`, `:(exclude)x` committed unrelated files). update-index refuses `.git` (any case) always and its HFS / NTFS look-alikes under `core.protectHFS` / `core.protectNTFS`; read-tree checks the same, hence those two only on update-index (a vault from before holding one must not stop taking writes).
- `git rm --cached` / `git commit` need a work tree (`fatal: this operation must be run in a work tree` with `--git-dir` alone): the cleanup by hand in docs/storage.md passes `--work-tree=tree`, after `read-tree HEAD`.
- Ruby: `Open3.capture3(..., binmode: true)` returns ASCII-8BIT: `Git#run` forces UTF-8 on its output (paths), else JSON warns about binary strings.
- Cloudflare: "Normalize incoming URLs" (default on) normalizes what its rules see — RFC 3986: dot segments removed, unreserved `%XX` decoded, `%2F` kept —, "Normalize URLs to origin" (default off) decides whether the origin gets that or the raw path. Off: an allowlist on `/files/` passed `/admin/../files/a%2f..%2f..%2flogin`. `raw.http.request.uri.path` is the path as sent ("may include some basic normalization"). Its docs disagree on whether `//` is always merged.
- `Rack::URLMap` matches the raw PATH_INFO with each `/` of the location as `/+`: `//admin/login`, `/admin//login`, `/admin/./login` reached Admin (`/ADMIN`, `/%61dmin`, `/files/../admin` stayed in App).
- rack-protection's `PathTraversal` (on by default in every Sinatra app) decodes `%2e` / `%2f` / `%5c`, turns `\` into `/` and resolves dot segments in PATH_INFO — after URLMap has routed the raw one.
- Puma joins a repeated header into one value (`X-Rock-Sync-Vault: notes, notes`), and `X_Rock_Sync_Vault` lands on the same Rack key (`HTTP_X_ROCK_SYNC_VAULT`; with both sent, Puma keeps the hyphenated one). A proxy rule must require exactly one hyphenated header equal to the vault, not "absent or equal". Puma itself refuses raw control characters and spaces in the request line (400, its own log line); for absolute-form (`GET http://host/x`) it sets PATH_INFO to the path, REQUEST_URI keeps the URL; fragments are dropped.
- curl removes `/./` and `/../` itself (not `//`, not `%2f`): checks of path tricks need `--path-as-is`.
- Errors live where Zeitwerk expects them: a file defines the constant its path names (`vault/errors.rb` holding `Vault::BadPath` would not autoload) — or nested in the class that raises them (`Git::Error`, `Vault::Path::BadPath`).
- Plugin uses `requestUrl` (not fetch): no CORS, works on mobile.
- Desktop `requestUrl` goes through Chromium's HTTP cache. A response with `Last-Modified` and no `Cache-Control` counts as fresh for about a tenth of its age, so a pull got the old version without asking the server (a 60-day-old note: days), status "Synced", `base` stale; a 304 in the server log for a request sent without `If-None-Match` is the same cache revalidating. Hence the server's `Cache-Control: no-store` and the plugin's `Cache-Control: no-cache` request header (`authHeaders`), which bypasses what's already cached. Recently edited files hide it: their freshness is seconds.
- Android `requestUrl` keeps response header names as sent (desktop lowercases them); a Go proxy in front (Tailscale) sends `Etag` → every `res.headers['etag']` was undefined, polls went out without `If-None-Match` and were answered at once, in a loop. Hence `lowerHeaders`; a poll answered 200 without an ETag backs off.
- Android `requestUrl` (Capacitor `requestUrlAndroid`) base64-encodes the whole body in Java (256 MB heap, several copies): ~36 MB → `OutOfMemoryError`, the app dies. Crash cause from the Mac: `adb logcat -b crash -d`. Hence `DEVICE_LIMIT`.
- `workspace.updateOptions()` keeps existing ViewPlugin instances: their `update()` must detect external state changes itself.
- `@codemirror/merge`'s `unifiedMergeView` (dropped, but if it comes back) needs `syntaxHighlightDeletions: false`: it parses deleted text with the editor's language outside the editor, and Obsidian's markdown parser crashes there (`null.viewport`). Its deletion widget text can't be selected by long-press on Android.
- `git merge-file` follows the global `merge.conflictStyle` (here diff3 → an extra `|||||||` base section): the server pins it with `-c merge.conflictStyle=merge`. If my last line had no trailing newline, git adds one inside a conflict; "Keep mine" then leaves a trailing newline (no text lost).
- `changeFilter` returning ranges: insertions exactly at a range boundary pass, deletions into it are suppressed. It runs before `transactionFilter`s, whose results aren't filtered again.
- `atomicRanges` + CM's delete commands: a deletion reaching into an atomic range extends to its edge (`skipAtomic`). Android doesn't go through those commands (raw DOM edits) — hence `editSeparator`.
- Conflict view editing model is testable in node with real CM packages (`@codemirror/state|view|commands` in a scratch dir, plus a stub `obsidian` module exporting `Platform` / `setIcon`): `import` `src/conflicts/editor.js`, run `deleteCharBackward` / `undo` on `{ state, dispatch }`. `conflicts/blocks.js` needs no stubs.
- Android: `--safe-area-inset-bottom` includes the open keyboard. Obsidian's generic `.workspace-leaf-content .view-content { padding-bottom: max(var(--safe-area-inset-bottom), …) }` then squeezes a custom view's content to a sliver above the keyboard (markdown views zero it via `[data-type='markdown']`); the conflict view zeroes it the same way.
- Switching to `.keep`: a device that still had a folder from before `.keep` existed pushes its `.keep` ("no base, only here") — a folder deleted elsewhere in the meantime comes back once, empty.
- git merge-file joins conflicts less than 3 lines apart into one block.
- Desktop CDP: start Obsidian with `open -a Obsidian --args --remote-debugging-port=9223`, then `localhost:9223/json`.
- Mobile console / DOM from the Mac: `adb forward tcp:9222 localabstract:$(adb shell cat /proc/net/unix | grep -o 'webview_devtools_remote_[0-9]*' | head -1)`, then `chrome://inspect` or CDP on `localhost:9222/json`.
- Obsidian's CSS: extract `app.css` from `~/Library/Application Support/obsidian/obsidian-*.asar` (`npx @electron/asar extract-file`).
- Desktop screenshot without focus: window id via `CGWindowListCopyWindowInfo` (owner "Obsidian", layer 0), then `screencapture -x -o -l<id>`.
- `git init --work-tree=…` stores the work tree as an absolute `core.worktree` in the repo's config; commands naming only the git dir (`cat-file`, `hash-object`) then fail once VAULTS_DIR sits elsewhere (`fatal: Invalid path`, every merge → 412). `Git#init` runs without it (every command passes `--work-tree`, now the git dir itself); repos created before: `git --git-dir=<repo.git> config --unset core.worktree`.
- `Rack::Session::Cookie` with `secure: true` commits the session only when `request.ssl?`: in production the proxy must send `X-Forwarded-Proto: https`, else the admin login never sticks (every POST → 403, no CSRF token in a session).
- Sinatra's `to()` / `url()` are absolute by default, so `redirect to('/x')` is too: Admin uses `redirect '/x'` with `prefixed_redirects` (+ `absolute_redirects` off) → `/admin/x`; forms use `url(path, false)`.
- Sequel on SQLite: `drop_column` / `drop_foreign_key` rebuild the table and lose its CHECK constraints — migration 002 rebuilds `devices` by hand (new table, copy, drop, rename; SQLite's rename updates references to it). An exception raised inside `DB.current.transaction` comes out as `Sequel::DatabaseError`: validate before opening it. Dropping a table other tables reference with `ON DELETE CASCADE` deletes their rows (with foreign keys on, DROP is a DELETE first): migration 009 turns them off around its rebuild (`no_transaction`, the pragma, then its own transaction on that connection).
- Zeitwerk's `push_dir` resolves relative paths against the cwd: environment.rb passes absolute ones (boot_test.rb runs config.ru from a temp dir).
- Docker: a uid without a passwd entry has `HOME=/` (not writable): Bundler warns and hunts for a temp home on every start → `BUNDLE_USER_HOME=/nonexistent` in the image. Puma re-raises SIGTERM after a graceful stop: as PID 1 that's exit 1 → `raise_exception_on_sigterm false`. Ruby buffers stdout when it isn't a TTY → `$stdout.sync = true` (config.ru).
- Docker Desktop's `credsStore: desktop` can hang (`docker-credential-desktop get` waiting on the Keychain) when run from a sandboxed shell: every pull / build stalls silently. Workaround: `DOCKER_CONFIG=<dir>` with `{"cliPluginsExtraDirs": [<absolute path of ~/.docker/cli-plugins>]}` + `DOCKER_HOST=unix://$HOME/.docker/run/docker.sock` (anonymous pulls). Not for `make push`: that needs the GHCR login.
- The server's git runs without the user's global / system git config (`Git::ENV_ISOLATED`): `commit.gpgsign` with 1Password's `op-ssh-sign` made every vault commit wait for a signing prompt (tests hung in `git commit`).
- `npm version` outside the repo's root (no `.git` in its cwd) bumps the files but neither commits nor tags: `plugin/Makefile` does both itself.
- The community directory lints every submission with `eslint-plugin-obsidianmd`: most rules as warnings, errors for `no-eval`, `no-implied-eval`, `no-unsanitized/*`, `regex-lookbehind`, `no-forbidden-elements` (no `<style>` / `<link>`) and, for new plugins, `no-static-styles-assignment`, `no-view-references-in-plugin`, `no-unsupported-api`, `platform`, `detach-leaves`, `no-plugin-as-component`, the settings heading rules. Its settings: docs/configuration.md in that repo.
- `.gitignore` entries for root-level build / state files need a leading `/`: `main.js` also hid `src/main.js`, `conflicts/` hid `src/conflicts/` (never committed until fixed).
- CM packages must stay external in esbuild (Obsidian provides them); a bundled second copy of `@codemirror/state` / `view` breaks facets and instanceof checks.
- Obsidian's `vault.read` / `cachedRead` / `process` drop a leading BOM; CRLF is kept. `vault.modify(file, '\uFEFF…')` writes the BOM. Hence hashes over `readBinary` only, and `exactText` (`TextDecoder` with `ignoreBOM`, `fatal`) for writes.
- Puma 8 `http_content_length_limit`: 413 from Content-Length (or a chunked body's running size) during parsing, logged as `HTTP parse error … Payload Too Large`; the request never reaches Rack.
- Obsidian's file explorer hides files whose type it can't open (`.zip`, `.csv`, `.af`, …) unless "Detect all file extensions" is on: internal `vault.getConfig` / `setConfig('showUnsupportedFiles')` (not in the public typings), stored in `.obsidian/app.json`.
- `app.saveLocalStorage(key, data)` / `loadLocalStorage(key)` (since 1.8.7): stored as JSON in `window.localStorage` under `<app.appId>-<key>` (`appId` = the vault's id, so per vault and per device); `data = null` removes the entry. Synchronous.
